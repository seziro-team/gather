# Test fixtures

These files exist **only** for the end-to-end suite and the demo scripts in `plan.md`.
Nothing here is rendered anywhere in the product (CLAUDE.md §4: fixtures are allowed inside
the test suite, and are labelled).

They are deliberately real files rather than a few bytes with the right extension, because
Gather's upload pipeline sniffs magic bytes instead of trusting a filename. A fixture that
is not genuinely a PDF proves nothing about a pipeline whose job is to work out what a file
actually is.

## Why an IRS form and not a made-up PDF

`plan.md` §9's Phase 3 demo script asks for "a real multi-page PDF". A real published tax
form is one, it is the exact kind of document Gather is built to collect, and it is in the
public domain so shipping it in an AGPL repository is unambiguous.

It replaces the `fixtures/real-w2.pdf` named in the original demo script. The 2026 Form W-2
is 2.1 MB — fifteen times the size — and nothing in the test depends on it being a W-2
rather than a W-9. Recorded as a Phase 3 deviation in `progress.md`.

## Why the photo is generated rather than downloaded

A real photograph of a real receipt would be someone's real receipt. The generator produces
a file with the properties that actually matter to the code under test — true handset
resolution, chroma subsampling, camera EXIF, the uneven lighting and slight motion blur of a
hand-held shot — with none of the properties that would make committing it a bad idea.

## Adding a fixture

Two rules, both of which exist because a fixture that lies is worse than no fixture:

1. **Say where it came from**, in the table above — a URL and a date for anything
   downloaded, a checked-in generator for anything synthesised.
2. **Do not commit anything that a scanner will quarantine.** Phase 6 tests virus handling
   with the EICAR string; that file will be written at test time by its own generator
   rather than stored here, so that nobody's antivirus eats a file inside their clone.
